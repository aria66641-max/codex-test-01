# 글결 · 한국어 블로그 SEO 작업실

HTML, CSS, JavaScript로 만든 무료 규칙 기반 글쓰기 도구입니다. 서버, API 키, 빌드, 외부 라이브러리 없이 사용합니다.

## 실행

저장소를 내려받은 뒤 **index.html을 최신 Chrome, Edge, Firefox 또는 Safari에서 여세요.** index.html, styles.css, app.js는 같은 폴더에 두세요. 모바일에서는 해당 파일을 열 수 있는 브라우저나 로컬 정적 파일 뷰어를 사용하세요. 별도 서버와 유료 API는 필요 없습니다.

1. 핵심 키워드를 입력하고 티스토리·네이버·워드프레스를 선택합니다.
2. 글쓰기 자료 만들기를 누릅니다.
3. 검색 의도 추정, 연관 키워드, 제목 3개, 메타설명, 130~160자 서론, H2 목차 및 가이드, FAQ 4개, 태그 8개를 확인합니다. 서론은 공백·문장부호 포함 유니코드 문자 수로 130~160자이며 긴 키워드는 서론에서만 축약합니다.
4. 결과별 복사 또는 전체 텍스트·티스토리 HTML 복사를 사용합니다. HTML에는 서론·H2 목차·FAQ가 들어가며 작성 지시문은 제외됩니다. 제목은 편집기의 제목란에 별도로 입력합니다. 태그와 메타설명은 플랫폼의 해당 설정란에서 직접 사용하세요.
5. 상단 키워드를 유지한 채 별도 제목과 본문을 입력해 SEO 체크리스트를 확인합니다. HTML h2 또는 Markdown의 `## 소제목`을 인식합니다. 일반 텍스트 소제목에도 `## `를 붙이세요.

자동 복사를 허용하지 않는 브라우저에서는 수동 복사 창이 표시됩니다. 입력은 저장하거나 외부로 전송하지 않으므로 페이지를 닫으면 사라집니다.

## 범위와 한계

- 실제 AI 본문 생성이 아닌 미리 정한 규칙과 문장 조합입니다. 목차의 가이드를 직접 작성한 근거와 사례로 바꿔야 합니다.
- 검색 의도는 단어 표현으로 추정하며 연관 키워드도 규칙 기반 확장입니다. 검색량, 검색 순위, 경쟁도는 측정하지 않습니다.
- 가독성은 문장·문단 길이, 키워드는 정확한 문자열, 제목과 소제목은 길이·구조로 점검합니다. 형태소, 의미, 사실, 전문성은 분석하지 않습니다.
- 편집 참고 기준이며 SEO 점수나 상위 노출을 보장하지 않습니다. 사실, 개인 경험, 가격, 최신 정보는 직접 확인하세요.
- 자동 게시, API 연결, 서버 저장 기능은 없습니다.

## 파일

- `index.html`: 한글 대시보드, 입력·결과·원고 점검 UI
- `styles.css`: PC·스마트폰 반응형 스타일
- `app.js`: 규칙 기반 생성, 점검, 안전한 HTML 내보내기와 복사
- `tests/smoke.cjs`: Playwright 브라우저 회귀 테스트 (사용자 실행에는 불필요)
- `README.md`: 실행·기능·한계·테스트 안내

## 검증 결과 (2026-10-29)

- `node --check app.js`: 통과
- Chromium + Playwright: 세 플랫폼, 결과 8종, 제목/FAQ/태그 개수, 예시 서론 길이, 빈 입력, 항목별/전체 복사 및 수동 복사 대체, HTML 이스케이프, Markdown/HTML 원고 점검 통과
- 375px, 768px, 1440px 화면 가로 넘침 없음
- 테스트 중 페이지 JavaScript 오류 및 외부 요청 없음
- 환경 관리 정책에서 `file://`을 차단하므로 직접 열기 테스트는 완료하지 못했습니다. 대신 Playwright 요청 가로채기로 로컬 정적 파일을 가상 주소에 제공하여 서버·외부 통신 없이 검증했습니다. 실제 모바일 기기와 Safari/Firefox는 별도 확인이 필요합니다.

개발 테스트는 Node.js와 Playwright, Chromium이 있을 때 `node tests/smoke.cjs`로 실행합니다. 시스템 브라우저 경로가 필요하면 `CHROMIUM_PATH=/usr/bin/chromium node tests/smoke.cjs`를 사용하세요. 이 환경의 대체 검증 명령은 `TEST_VIRTUAL_ORIGIN=1 CHROMIUM_PATH=/usr/bin/chromium node tests/smoke.cjs`입니다.

변경 사항은 로컬 작업 트리에 남겼으며 GitHub 병합·배포는 수행하지 않았습니다.

## 검색 의도별 생성 개선

신청방법, 발급방법, 비용, 자격조건, 비교·선택, 뜻·개념, 오류 해결, 일반 실행 방법, 정보 탐색의 9개 유형을 지원합니다. 각 유형에 서로 다른 제목 3개, H2 목차, 서론, FAQ 질문, 태그 묶음을 사용합니다. 검색 통계나 실제 검색자 조사 결과는 아닙니다.

복합 키워드는 오류 해결 → 신청 → 발급 → 비용 → 자격 → 비교 → 뜻 → 일반 방법 순서로 주된 의도를 결정하며, 함께 감지한 다른 의도도 표시합니다. 예를 들어 ‘등본 발급 비용’은 발급을 주된 의도로 잡고 비용도 감지했다고 표시합니다. 정교한 문맥 분석을 수행하지 않으므로 의도를 잘못 추정할 수 있습니다.

FAQ의 실제 답을 확인할 자료가 없으므로 구체적인 질문과 ‘확인 필요 — 확인하지 못한 내용’을 제공합니다. 확인하지 않은 가격·기간·자격·절차를 만들어내지 않습니다. 독자용 콘텐츠 초안과 작성자 전용 가이드를 별도 영역으로 제공하며, 전체 텍스트 복사에도 영역을 표시합니다. 티스토리 HTML은 가이드를 제외하지만 아직 검증되지 않은 FAQ 상태는 보존합니다.

태그는 키워드 한 개와 검색 의도에 관련된 서로 다른 용어 일곱 개로 구성하며, 같은 키워드에 접미사를 반복해서 붙이지 않습니다. 실제 인기 태그나 검색량으로 검증한 추천은 아닙니다.

추가 테스트: `node tests/intents.cjs` — 9개 의도, 63개 서론 경계 사례, 복합 의도 우선순위, 태그 중복, FAQ 확인 필요 표시, HTML/전체 텍스트의 가이드 분리 검증 통과. 기존 브라우저 테스트는 결과 카드가 8개로 늘어난 점과 서론 상한 160자를 반영했으며, 의도별 화면 생성 검증도 추가했습니다.

## SEO 도구 v2.1

화면 상단의 **SEO 도구 v2.1**과 제목 표시줄로 버전을 확인하세요. 반드시 ZIP 전체를 새 폴더에 압축 해제한 후 그 폴더의 index.html을 여세요. 예전 폴더의 바로가기와 혼용하지 마세요. index.html은 app.js?v=2.1과 styles.css?v=2.1을 참조하며 JavaScript 실행 버전도 HTML의 data-seo-version에 표시합니다.

보조금24 신청방법 회귀 사례: 서론 148자, 보조금24·정부24·정부혜택·맞춤혜택조회·지원대상확인·신청기간·구비서류·접수기관 태그 8개를 제공합니다. FAQ는 혜택 찾기, 사업별 신청 경로, 구비서류, 금액·결과 확정을 구분합니다. 정부24 안내(https://www.gov.kr/, 자료 확인일 2026-10-29)를 바탕으로 로컬 참고 문구를 저장했으며 실행 중 웹 조회는 하지 않습니다. 개별 사업의 자격·금액·기한은 미확인으로 남깁니다. 신청 이외 의도의 규칙은 유지합니다.

`node tests/v21.cjs`로 특정 키워드의 모듈 회귀 테스트를 실행합니다. `SEO_ROOT` 환경 변수로 실제 압축 해제 폴더를 지정해 v21 및 smoke 테스트를 동일하게 실행할 수 있습니다. 배포 ZIP은 index.html, styles.css, app.js, README.md 4개만 포함합니다. 테스트 스크립트는 개발 저장소에서 실행합니다.
