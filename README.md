# 글결 · 한국어 SEO AI 글쓰기 2.2.1

안정 버전 `seo-v2.1-stable`을 보존한 `feature/ai-writing`의 실행용 개발 결과물입니다. 기존 규칙 기반 도구와 AI 본문 작성 화면을 함께 제공합니다. 실제 API 연동은 구현했지만 **실제 유료 API 테스트는 하지 않았습니다.**

## Windows에서 실행

1. 최종 실행용 ZIP **전체를 새 폴더에 압축 해제**합니다.
2. Node.js 20 이상(LTS 권장)이 설치된 상태에서 **START.bat**을 더블클릭합니다.
3. 서버가 준비되면 `http://127.0.0.1:3000`이 자동으로 열립니다. 실행 창을 닫으면 서버가 종료됩니다.

패키지 설치나 CMD 명령 입력은 필요 없습니다. `.env`가 없으면 키가 없는 데모 설정을 자동으로 생성합니다. 키·모델·활성화 설정이 올바르지 않거나 3000 포트가 사용 중이면 실행 전에 안내합니다. 상세한 초보자 안내는 **실행안내.md**를 읽으세요.

기존 규칙 기반과 데모는 `index.html` 직접 열기도 가능합니다. 실제 AI는 로컬 서버가 필요합니다. macOS/Linux는 `node launcher.cjs` 또는 `npm start`를 사용하세요.

## 실제 AI 설정 — 사용자가 로컬 PC에서만 수행

자동 생성된 `.env`를 로컬 텍스트 편집기로 열고 다음 세 항목을 설정한 후 서버를 다시 실행합니다.

- `ENABLE_LIVE_AI=true`
- `OPENAI_API_KEY`: 본인 OpenAI API 키
- `OPENAI_MODEL`: 본인 계정이 사용할 수 있는 Responses 및 Structured Outputs 지원 모델 ID

`PORT=3000`을 유지하세요. 모델은 계정별 가용성을 확인해 설정하며, 앱이 임의로 모델을 선택하거나 API 호출로 확인하지 않습니다. `.env`는 ZIP·GitHub·웹 정적 파일에서 제외됩니다. API 키를 HTML, JavaScript, 질문 입력란에 넣거나 공유하지 마세요. 실행기는 키 값을 출력하지 않습니다.

화면 기본값은 **데모 모드**입니다. 설정 후 사용자가 실제 AI 모드를 선택하고 생성 버튼을 누를 때만 요청이 발생합니다. 시작·화면 열기·입력·수정·점검·복사만으로 API 요청이 발생하지 않습니다. 자동 유료 재시도는 없고, 생성 클릭당 한 번의 Responses API 요청만 수행합니다. 다시 생성 버튼을 누르면 새 유료 요청입니다.

## 기능과 출력 계약

- 키워드, 티스토리·네이버·워드프레스, 길이, 글쓰기 톤 입력
- 검색 의도에 맞는 제목 3개, 공백 포함 서론 130~160자
- H2 본문 3~8개, 공백 포함 1800~2000자 (선택 시 1800~1900 또는 1900~2000)
- 친근한 정보성 문체, 실제 독자 질문 FAQ 4개, 공감형 결론, 관련 태그 8개
- 제목 선택 및 제목·본문·전체 텍스트·전체 HTML 복사, 항목별 복사
- 발행 전 구조·글자 수·키워드·정확한 문장 반복 점검과 기존 SEO 체크리스트
- API 오류·거절·빈 출력·잘못된 JSON·토큰 잘림·분량 오류 안내

문자열은 NFC 정규화, CRLF/CR→LF 변환, 앞뒤 공백 제거 후 유니코드 코드 포인트 수로 계산합니다. 내부 공백·줄바꿈을 포함합니다. 본문은 H2 body를 LF 두 개로 연결한 값이며 제목·소제목·서론·FAQ·결론·태그를 제외합니다. 서버와 브라우저가 같은 검증기를 사용합니다.

OpenAI Responses API `/v1/responses`, strict JSON Schema, `store:false`와 12000 출력 토큰 상한을 사용합니다. 프롬프트는 기본 본문 목표 1900자, H2 5개에 약 378~379자씩 서로 다른 설명을 배분하고, 독자의 목적·준비사항·진행·주의사항을 보완하도록 합니다. 생활정보·자동차·지원사업에 서로 다른 설명 흐름을 적용합니다. 반복 문장·허위 경험·출처를 만들지 않도록 지시합니다.

## 분량 부족 처리와 발행 전 검토

모델이 정확한 글자 수를 따르는 것을 프롬프트나 토큰 상한만으로 보장할 수 없습니다. 부족한 응답을 성공으로 표시하거나 의미 없는 문장으로 자동 보충하지 않습니다. 구조가 정상인 분량 미달 초안은 **원고 수정 및 분량 점검** 편집기에 보존합니다. API 호출 없이 설명을 보완하고 점검 버튼으로 적용할 수 있습니다. 기준을 통과할 때까지 복사를 잠그며, 오류에는 현재 길이와 요구 범위를 표시합니다. 구조가 깨진 응답은 보존하지 않습니다.

불확실한 내용은 ‘확인 필요’로 표시하도록 지시합니다. 근거가 없는 정책별 자격·금액·구비서류·메뉴·지급일과 실제 개인 경험을 만들어내지 않습니다. 검색이나 자동 사실 검증 기능은 없으므로 사용자도 모든 주장을 검토해야 합니다. 데모 FAQ는 미확인임을 보여주는 샘플이며 실제 정책 답변이 아닙니다. SEO 점수나 상위 노출을 보장하지 않습니다.

로컬 서버는 127.0.0.1에 바인딩하고 허용 목록에 있는 정적 파일만 제공합니다. 실제 AI는 동일 출처 JSON 요청, 입력 크기 제한, 동시 요청 1개를 적용합니다. 응답·키를 로그에 남기지 않습니다. 개인정보를 키워드에 넣지 마세요. 실제 모드 입력은 서버와 OpenAI로 전송됩니다. 로컬 영구 저장과 자동 게시 기능은 없습니다. 공개 인터넷 서비스용 인증·사용량 할당량은 구현하지 않았으므로 공개 배포용 서버로 사용하지 마세요.

## 테스트 및 검증 범위

- `npm test`: 기존 규칙 기반 회귀, 108개 데모 조합, 출력 스키마·길이 경계·정규화, Responses 요청 계약, API 오류·거절·미완료, 자동 재시도 없음, 개인정보 비노출, 설정·런처 검사
- 보조금24 신청방법·생활정보 정리·자동차 관리: 로컬 HTTP → 모의 Responses → 출력 검증 통합
- 124자 서론·1148자 본문 거부 및 편집용 초안 보존, 정상 응답, 잘못된 형식, API 한도 오류 검증
- `npm run test:browser`: 기존 기능과 AI 화면, 복사, 분량 미달 원고 수정·재검증, XSS 방지, 375/768/1440px 반응형
- 브라우저 테스트만 Playwright 설치가 필요합니다. `npm install` 후 `npx playwright install chromium`을 실행합니다. 일반 사용자 앱 실행에는 설치가 필요 없습니다.
- 환경 정책에서 file URL이 차단되어 `TEST_VIRTUAL_ORIGIN=1 CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`로 로컬 자산을 제공해 검증했습니다.

자동 테스트와 압축 해제본 통합 테스트는 통과했습니다. **실제 유료 API 요청·실제 Windows PC의 .bat 더블클릭·실제 모바일 기기 검증은 수행하지 않았습니다.** Windows 실행기의 설정 및 서버 준비 로직은 Node 테스트로 검증했습니다. 실제 모델 응답 품질과 계정별 호환성은 사용자의 첫 실행에서 확인해야 합니다.

## 파일 구성

`START.bat`, `launcher.cjs`, `.env.example`은 실행기이며 `server/`는 서버 전용 모듈입니다. `ai-core.js`, `ai-ui.js`는 AI 계약·데모·UI, `app.js`는 유지한 규칙 기반 도구입니다. `tests/`는 자동 테스트, `tools/package.py`는 비밀 설정과 과거 ZIP을 제외하고 실행용 ZIP을 만드는 스크립트입니다.

API 참고: https://developers.openai.com/api/reference/resources/responses/methods/create

main·seo-v2.1-stable은 변경하지 않으며 자동 배포·병합을 수행하지 않습니다.

## 정보성 원고 품질 개선 (2026-10-30)

변경 전 정상 커밋 `929d40f91972c98b4253944b1039dec0b8efd2c6`은 `backup/ai-writing-before-quality-2026-10-30` 브랜치에 보존했습니다. main과 seo-v2.1-stable은 변경하지 않습니다.

`server/content-plan.cjs`는 검색 의도와 질문 우선순위를 규칙으로 추정합니다. 신청·발급·비용·자격·비교·뜻·오류 해결·실행 방법을 구분하고 보조금24와 자동차 관리의 독자 질문을 별도로 구성합니다. 이는 실제 검색량이나 검색 결과를 수집한 분석이 아닙니다. 첫 H2 첫 두 문장에서 핵심 답 또는 판단 기준을 제시하도록 지시합니다.

각 H2는 행동·판단 기준·준비사항·예외를 구분하고, FAQ는 질문에 직접 답하며 본문을 반복하지 않도록 보강했습니다. 제목별 관점을 다르게 하고, 주제 고유의 소제목과 짧은 문단, 문맥에 맞는 키워드 사용을 지시합니다. 강제 키워드 밀도나 노출 보장은 없습니다. 서론·본문 분량과 출력 개수·검증 기준은 그대로입니다.

현재 실제 AI 경로에는 웹 조회 도구가 없습니다. 따라서 정책·금액·신청 기한·최신 변경 사항은 ‘검증 필요’로 표시하도록 지시하고, 모델 기억이나 과거 지식을 실제 공식 조회로 취급하지 않습니다. 화면에도 공식 출처 미조회 상태를 표시합니다. 공식 URL, 조회일, 개인 경험을 임의로 만들지 않습니다. 프로그램이 모든 사실을 자동 판정하거나 허위 주장을 완벽히 차단하는 것은 아니므로 발행 전 검토가 필요합니다.

편집 점검은 문장부호·공백 차이를 정리한 반복 문장, 문자 3-gram 유사도 기반 유사 문장 후보, 100자 초과 문장, 추상적 H2 및 최신 주장 검토 후보를 표시합니다. 휴리스틱 경고이므로 의미 중복·사실 여부의 판정이나 SEO 점수가 아닙니다. 자동으로 내용을 삭제하거나 분량을 채우지 않습니다.

추가 `tests/quality.cjs`는 9개 키워드 의도·질문 계획, 출처 미조회와 검증 필요 지침, 모의 요청의 웹 도구 부재·단일 호출, 편집 경고를 검증합니다. 기존 전체 기능·실행기·브라우저 테스트와 압축 해제본 테스트도 통과했습니다. 실제 유료 API 생성 품질·실제 Windows 더블클릭·공식 웹 조회·실제 검색 노출 성과는 검증하지 않았습니다.
